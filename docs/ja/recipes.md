| パターン | 入れ方 | 鍵の扱い | 端末の守り方 |

## iPhone ・ すぐ使う {#ios-pages}

信頼するもの: このサイト(入れる時点)、WebKit、Appleアカウント。失う利便性: ネットにつながないこと以外はほとんどありません。

入れる:

1. 鍵を入れる前のiPhoneで、[Webアプリ](https://habakan.github.io/bitwasm-signer-app/app/)をSafariで開く。URLが`habakan.github.io/bitwasm-signer-app/app/`か確かめる
2. 共有メニューの「ホーム画面に追加」で入れ、ホーム画面から開く
3. 「オフラインの準備をしています」が消えるまで、ネットにつないだまま開いておく
4. 設定 › このアプリの版 を、リリースノートの「Web app build」と比べる
5. 機内モードにする。ネットにつながっている間は鍵を読み込めず、読み込んだ鍵は消去します

使う:

1. Appleアカウントにサインインし、iCloudキーチェーンをオンにしておく(iOS 18以降)
2. 設定 › 鍵の保存 をオンにし、鍵を読み込んで保存する
3. パスフレーズは標準キーボードで入力する
4. 更新したいときだけネットにつなぎ、ホーム画面に戻ってから開き直す。版をもう一度確かめる

## iPhone ・ 配る人も自分 {#ios-fork}

信頼するもの: 選んだコミット、自分のGitHubアカウント、WebKit。失う利便性: 開くたびにシードかSeedQRを読み込みます。後でこのサイトやリポジトリが乗っ取られても、入れた版には関係しません。

入れる:

1. このリポジトリをforkする。入れたい版があれば、そのタグかコミットをforkのmainにする
2. forkのActionsタブで、ワークフローを有効にする(forkでは最初は無効です)
3. forkのSettings › Pagesで、Sourceを「GitHub Actions」にする
4. Actions › Pages › Run workflowで一度ビルドする。終わると、実行結果の要約に「web app build」が出ます
5. `https://<自分のユーザー名>.github.io/bitwasm-signer-app/app/`を、上のパターンの手順1〜3と同じようにホーム画面に入れる
6. 設定 › このアプリの版 が、4の名前や、同じコミットのリリースノートの「Web app build」と同じか確かめ、機内モードにする

使う:

1. 鍵は保存せず、使うたびにシードかSeedQRで読み込む
2. 終わったら「ウォレットを閉じる」。アプリを離れても鍵は消えます
3. パスフレーズは標準キーボードで入力する

入れたあとはforkを消してもかまいません。ホーム画面のアプリは取り込んだファイルだけで動きます。forkを残す場合は、自分のgithub.ioの下にある他のページとオリジンを共有することに注意してください。

## Android ・ 手軽 {#android-apk}

信頼するもの: 作者のリリース、導入ページ、PC。失う利便性: 機能制限を「必須」にした項目は、オフにするまで鍵を読み込めません。署名用のスマホは一度もネットにつなぎません。

入れる:

1. スマホで開発者向けオプションを出し(端末情報のビルド番号を7回タップ)、USBデバッグをオンにする
2. PCで[リリース](https://github.com/habakan/bitwasm-signer-app/releases)からAPKと`SHA256SUMS`をダウンロードする
3. [導入ページ](https://habakan.github.io/bitwasm-signer-app/install/#apk)を「APK だけ入れる」で開き、APKと`SHA256SUMS`を選ぶ。一致したときだけ入れられる
4. 入れ終わったらUSBデバッグをオフにし、機内モードにする

使う:

1. 設定 › 端末の機能制限 で、ネットワーク、Bluetooth・NFC、サードパーティ製キーボード、USBデバッグ、ユーザー補助を「必須」にする
2. 画面ロックを設定し、鍵を保存する(Android Keystore。Googleアカウントは不要)
3. パスフレーズは標準キーボードで入力する

## Android ・ 専用機 {#android-lockdown}

信頼するもの: 作者のリリース(USBで入れるなら導入ページとPCも)。失う利便性: 端末をほかの用途に使えません。詳しい手順は[Signer Lockdown](lockdown.md)にあります。

入れる:

1. 端末を工場出荷リセットする。アカウントは1つも追加しない
2. 次のどちらかで Lockdown を入れる
   - QR: ようこそ画面の同じ場所を6回タップし、Wi-Fiにつないでリリースの`provisioning-<version>.png`を読む。PCは画像を表示するだけで、中身はリリースが決めます([QRで導入する](lockdown.md#qr-で導入する))
   - USB: 一度もネットにつなぎません。先に画面ロックを設定してUSBデバッグをオンにし、PCの導入ページで Lockdown のAPKと`SHA256SUMS`を選んで入れる([ネットワークを使わずに導入する](lockdown.md#ネットワークを使わずに導入する))
3. 画面ロックを設定する。Googleアカウントは追加せず、Google Servicesの画面のスイッチはすべてオフにする
4. Signer Lockdown を開いて「署名アプリを入れる」、機内モードをオンにして「制限を適用」

使う:

1. 鍵を保存する(Android Keystore)
2. 必要なら 設定 › 端末の機能制限 も「必須」にする
3. 更新は、SDカードか、Lockdownの「PC から USB でアプリを更新」で行い、`SHA256SUMS`と照合する
4. 状態を確かめたいときは、制限を一時解除して PC から`lockdown/audit.sh`を実行する

## 自分でビルド {#build}

信頼するもの: ソースとビルド環境。失う利便性: ビルドの手間。iOSは開発者アカウントでの署名が要ります。

入れる:

1. ソースを読み、READMEの[ビルド](https://github.com/habakan/bitwasm-signer-app#build)の手順に従う。Androidはリリースビルドにする(デバッグビルドはスマホではとても遅い)
2. Android: `adb install`か、導入ページの「APK だけ入れる」で入れる
3. iOS: Xcodeで自分の開発者アカウントで署名して入れる
4. 機内モードにする

使い方は、上のどのパターンとも組み合わせられます。作者のリリースとは署名鍵が違うので、リリースのAPKの上からは更新できません。
