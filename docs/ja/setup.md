# セットアップ方法

<sup>[English](../setup.md)</sup>

署名アプリの入れ方はいくつかあります。どれを選ぶかは、何を信頼するかで決まります。信頼するものが少ないほど手間が増えます。

## 選び方

| 方法 | 信頼するもの | 署名用のスマホがネットにつながるか | 対応 |
| --- | --- | --- | --- |
| [自分でビルドする](#build) | ソースコード(自分で読める)とビルド環境 | つながない | Android、iOS |
| [リリースのAPKをUSBで入れる](#release-usb) | GitHubのリリースと導入ページ、PC | つながない | Android |
| [Lockdownを入れる(USB)](#lockdown-usb) | GitHubのリリースと導入ページ、PC | つながない | Android |
| [Lockdownを入れる(QR)](#lockdown-qr) | GitHubのリリース | 導入の間だけWi-Fiにつなぐ(まだ鍵はない) | Android |
| [Webアプリをホーム画面に入れる](#pwa) | 入れた時点のGitHub Pages | 導入の間だけつなぐ(まだ鍵はない) | iOS、Android |
| [Webアプリを自分のPagesから入れる](#pwa-fork) | 選んだコミットのソースと自分のGitHubアカウント | 導入の間だけつなぐ(まだ鍵はない) | iOS、Android |

APKとiOSアプリは、読み込むWASMモジュールのSHA-256を確かめ、一致しなければ動きません。Webアプリでは確かめるコード自体もサイトから届くので、この確認はサイトの差し替えを防げません。

## 何を信頼することになるか {#trust}

- **GitHubのリリース**: リリースのAPKは作者の鍵で署名され、同じリリースに`SHA256SUMS`が付きます。`SHA256SUMS`で分かるのはダウンロードが壊れていないことで、リリースそのものが差し替えられた場合は見抜けません。一度入れると、Androidは同じ鍵で署名された更新しか受け付けません。
- **導入ページ**: [導入ページ](https://habakan.github.io/bitwasm-signer-app/install/)はブラウザ(ChromeかEdge)からWebUSBでスマホに書き込みます。つないでいる間は、スマホに対してadbのすべての操作ができます。ページはこのリポジトリからビルドしたものです。
- **PC**: USBでつなぐ方法では、PCとそのブラウザも信頼します。QRで入れる方法では、PCはQRを表示するだけです。
- **GitHub Pages**: Webアプリは、ホーム画面に入れて最初に開いたときにサイトから全ファイルを取り込み、その後はオフラインで動きます。その時点のサイトの中身を信頼します。その後は取り込んだ版だけを使いますが、ネットにつながると新しい版が届き、次に開いたときに切り替わります。サイトが乗っ取られていると防げないので、入れたあとはネットにつながないでください。動いている版は 設定 › このアプリの版 で確かめられます。GitHubのActionsでビルドすれば、同じコミットからは同じ版の名前になるので、リリースノートの「Web app build」と比べられます(手元のMacなど、別の種類のマシンでビルドすると一致しません)。
- **ビルド環境**: 自分でビルドするときは、Rust、Android SDKやXcode、npmの依存パッケージを信頼します。

## 自分でビルドする {#build}

リリースを信頼したくない場合です。ソースを読み、自分のPCでビルドして入れます。

- Android: READMEの[ビルド](https://github.com/habakan/bitwasm-signer-app#build)の手順でAPKを作り、`adb install`か導入ページの「APK だけ入れる」で入れます。デバッグビルドはスマホではとても遅いので、リリースビルドを使ってください。
- iOS: 配布はしていないので、Xcodeで自分の開発者アカウントで署名して入れます。iOSはシミュレーターでしか確認していません。

自分でビルドしたAPKは作者のリリースと署名鍵が違うので、リリースのAPKの上から更新することはできません。

## リリースのAPKをUSBで入れる {#release-usb}

署名用のスマホを一度もネットにつながずに、APKだけを入れます。

1. スマホで開発者向けオプションを出し(端末情報のビルド番号を7回タップ)、USBデバッグをオンにする
2. PCで[リリース](https://github.com/habakan/bitwasm-signer-app/releases)からAPKと`SHA256SUMS`をダウンロードする
3. [導入ページ](https://habakan.github.io/bitwasm-signer-app/install/#apk)を「APK だけ入れる」で開き、APKと`SHA256SUMS`を選ぶ。一致したときだけ入れられる
4. 入れ終わったらUSBデバッグをオフにし、機内モードにする

## Signer Lockdownを入れる {#lockdown}

Androidでは、工場出荷リセットしたスマホを[Signer Lockdown](lockdown.md)で署名専用機にできます。機内モードを固定し、USBデバッグ、アプリやアカウントの追加を禁止します。署名アプリはLockdownに同梱されています。

### USBで入れる {#lockdown-usb}

スマホを一度もネットにつなぎません。上の「リリースのAPKをUSBで入れる」と同じように導入ページを使い、Lockdownを入れてDevice Ownerにします。手順は[ネットワークを使わずに導入する](lockdown.md#ネットワークを使わずに導入する)を参照してください。

### QRで入れる {#lockdown-qr}

PCはQRを表示するだけです。スマホはLockdownをダウンロードする間だけWi-Fiにつながり、QRに入っているSHA-256で照合します。手順は[QRで導入する](lockdown.md#qr-で導入する)を参照してください。

## Webアプリをホーム画面に入れる {#pwa}

同じ署名エンジンをブラウザで動かします。iPhoneでは、自分で署名せずに入れられる唯一の方法です。

1. 鍵を入れる前のスマホで、[Webアプリ](https://habakan.github.io/bitwasm-signer-app/app/)をSafari(iPhone)かChrome(Android)で開く
2. 共有メニューかメニューの「ホーム画面に追加」で入れ、ホーム画面から開く
3. 「オフラインの準備をしています」が消えるまで、ネットにつないだまま開いておく。iPhoneでは、ホーム画面から開いたときに取り込み直します
4. 機内モードにする。ネットにつながっている間は鍵を読み込めず、読み込んだ鍵は消去します

ネイティブアプリとの違いがあります。

- シードフレーズは、ネイティブアプリと同じアプリ内のキーで入力するので、キーボードを通りません。パスフレーズはキーボードで入力し、サードパーティ製キーボードは止められないので、端末に最初から入っているキーボードを使ってください。
- 鍵は、設定 › 鍵の保存 をオンにすると保存できます。このアプリのパスキーで暗号化し、開くたびにFace ID、指紋、または端末のパスコードを求めます。端末のパスコードを知る人は開けること、ブラウザのデータは消えることがあり紙のバックアップが必須であることに注意してください。新しいウォレットの作成はできません。
- iPhoneでパスキーを作るには、Appleアカウントへのサインインと、iCloudキーチェーンの同期が必要です。保存した鍵を開くときも必要で、サインアウトすると、キーチェーンのコピーをこのiPhoneに残しても開けません。パスキーは同じアカウントの端末に同期されます。暗号化した鍵はこの端末のブラウザにしかないため、ほかの端末のパスキーだけでは開けませんが、署名用のiPhoneをアカウントに入れることになります。それを避けたい場合は、鍵を保存せずメモリのみで使ってください。
- 鍵の保存は主にiPhone向けです。Androidのパスキーはふつう Google アカウントへのサインインが必要で、アカウントの追加を禁止する Signer Lockdown とは両立しません。Androidでは、Googleアカウントなしで画面ロック付きの Android Keystore に保存できるネイティブ版を使ってください。
- ネットにつながったかどうかは、ブラウザが知らせる範囲でしか分かりません。
- スクリーンショットと画面収録を止められません。アプリを離れると画面を隠して開き直しますが、アプリ切り替えの画面に残らないかはブラウザ次第です。
- 偽のサイトから入れないよう、開く前にURLが`habakan.github.io/bitwasm-signer-app/app/`か確かめてください。

実機のiPhoneではまだ確認していません。シミュレーターとデスクトップのChromeで確認しています。

### 自分のPagesから入れる {#pwa-fork}

このサイトを信頼する代わりに、自分のGitHubアカウントで同じアプリをビルドして入れます。後でこのサイトやリポジトリが乗っ取られても、入れた版には関係しません。

1. このリポジトリをforkする。入れたい版があれば、そのタグかコミットをforkのmainにする
2. forkのActionsタブで、ワークフローを有効にする(forkでは最初は無効です)
3. forkのSettings › Pagesで、Sourceを「GitHub Actions」にする
4. Actions › Pages › Run workflowで一度ビルドする。終わると、実行結果の要約に「web app build」が出ます
5. `https://<自分のユーザー名>.github.io/bitwasm-signer-app/app/`を、上の手順と同じようにホーム画面に入れる
6. 設定 › このアプリの版 が、4の名前や、同じコミットのリリースノートの「Web app build」と同じか確かめる

入れたあとはforkを消してもかまいません。ホーム画面のアプリは取り込んだファイルだけで動きます。forkを残す場合は、自分のgithub.ioの下にある他のページとオリジンを共有することに注意してください。

## 入れたあと {#after}

- 機内モードにし、どのネットワークにもつながないようにします(Lockdownでは固定されます)。
- 署名アプリの 設定 › 端末の機能制限 で、ネットワークやサードパーティ製キーボードなどがオンのときの扱いを選べます。
- Lockdownを入れたスマホは、制限を掛ける前か一時解除した後に、PCから`lockdown/audit.sh`で状態を確かめられます。
